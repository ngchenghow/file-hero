# 给 AI 的说明：为视频写描述

这个文件夹由 File Hero 管理（手机和电脑共用）。请按下面的方法，看视频截图，为还没有描述的视频写描述。

## 要做的事

1. 查看这个文件夹和所有子文件夹。每个文件夹里有一个 `file-readme.txt`，记录这个文件夹里每个文件的信息。
2. 在 `file-readme.txt` 里找出**同时满足**下面两个条件的视频：
   - 有 `Thumbnails:` 行（列出了 3 张截图）；
   - `Description:` 后面是空的。
3. 打开这 3 张截图（路径相对于该 `file-readme.txt` 所在的文件夹，例如 `thumbs/京都.mp4-1.jpg`），它们是视频开头、中间、结尾附近的画面。
4. 用**中文写一到两句话**描述视频内容，写进该视频的 `Description:` 行。
5. 全部完成后，列出写了描述的视频，以及因为截图缺失或打不开而跳过的视频。

## file-readme.txt 的格式

文件开头是文件夹本身的信息，之后每个文件一段，以 `[File: 文件名]` 开头，下面每行是 `键: 值`（冒号后有一个空格）：

```text
[File: 京都.mp4]
Description:
First-Indexed-UTC: 2026-09-25T10:00:00Z
Last-Stored-UTC: 2026-09-25T10:00:00Z
Modified-UTC: 2026-09-20T08:12:00Z
Name: 京都.mp4
Size-Bytes: 21108377
Thumbnails: thumbs/京都.mp4-1.jpg | thumbs/京都.mp4-2.jpg | thumbs/京都.mp4-3.jpg
```

写好后只有这一行改变：

```text
Description: 傍晚的京都石板街上游人往来，两旁是木造町屋和亮起的灯笼。
```

## 规则（请严格遵守）

- **只改**描述为空的视频的 `Description:` 行。已有描述的不要改，文件开头那段（文件夹本身）的 `Description:` 也不要改。
- 描述必须写在同一行：`Description: ` 后面直接接文字，**不能换行**。
- 不要改动任何其他行，不要增删空行，不要调整顺序，保持 UTF-8 编码。
- 不要新建、重命名、移动或删除任何文件；不要改动 `thumbs` 文件夹里的截图。
- 如果某个文件夹里有 `file-readme.txt.tmp` 或 `file-readme.txt.backup`，说明 File Hero 正在写入，**跳过这个文件夹**，最后告诉用户。
- 如果某段缺少 `Description:` 行，在该段 `[File: ...]` 下面加一行 `Description: 描述内容`。

## 描述怎么写

- 中文，一到两句，直接写画面内容，不要用「这段视频」「截图中」之类的开头。
- 写看得到的：场景和地点类型、人物在做什么、穿着、主要物品（例如车辆能看出品牌和车型时写出来）、天气和时间（白天、夜晚）。
- 三张截图不同时，概括整个视频的内容或变化，例如「先在门口试穿白色西装，再转身展示背面」。
- 不要猜看不出来的信息，例如人名或确切地址。文件名和文件夹名可以作为线索，但以画面为准。
